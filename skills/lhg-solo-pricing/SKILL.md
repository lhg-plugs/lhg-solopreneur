# lhg-solo-pricing：定价策略

> 目标：输出一份"敢收钱、收得到"的定价方案。
> 核心纪律：**免费用户是成本，付费用户才是验证。**定价太低是独立开发者最常见的死法。

## 1. 何时使用

- MVP 范围已定（lhg-solo-mvp 完成），准备写定价页时 → 跑本 skill
- 已上线但转化率低、怀疑定价有问题时 → 用第 5 步做价格测试
- 纯免费工具、无商业化打算 → 不用跑（但建议至少想清楚"以后靠什么活"）

## 2. 输入与输出

- **输入**：产品一句话、目标用户、P0 功能清单
- **输出**：`pricing.md`，包含：定价模型选择、价格档位、锚定设计、退款/取消政策、支付方式、合规声明、FAQ

## 3. 三模型选型（先选模型，再定数字）

### 3.1 订阅制（月付/年付）

- **适合**：持续提供价值的产品（SaaS 工具、内容更新、数据服务）
- **优点**：现金流可预测，一人公司最稳的模型
- **必须**：明确写"可随时取消"；自动续费必须有到期提醒
- **定价起点**：年付 ≈ 月付 × 10（两个月折扣是行业惯例）

### 3.2 买断制（一次性付费）

- **适合**：工具类、解决一次性问题的产品（模板、插件、小工具）
- **优点**：决策门槛低，用户不讨厌；缺点：需要持续获客
- **注意**：买断 ≠ 终身免费更新，更新政策要写清（"含 1 年更新"比"终身"更可持续）

### 3.3 免费增值（Free + 付费档）

- **适合**：有自然传播属性、免费版本身就是广告的产品
- **红线**：免费版不能是"残废版"（没人用的免费版带不来付费转化），也不能太慷慨（人人用免费版你喝西北风）
- **检验标准**：免费版解决"用起来"，付费版解决"离不开"

### 3.4 选型决策

问三个问题，答案决定模型：

1. 用户是"持续用"还是"用完即走"？→ 持续用选订阅，用完即走选买断
2. 有没有自然传播？→ 有且强，考虑免费增值
3. 你更缺现金流还是更缺用户？→ 缺现金流选订阅/买断先收钱，缺用户选免费增值

## 4. 定价数字四步法

### 4.1 成本倒推（下限）

月成本（服务器+第三方+你的时间折价）÷ 目标付费用户数 = 单用户成本下限。
定价绝不能长期低于这个数——**低于成本的定价是自杀**。

### 4.2 竞品对标（参照系）

列 3 个竞品的价格，回答："我凭什么比它贵/便宜？"
没有参照系的价格，用户只能用"贵/便宜"这种情绪投票。

### 4.3 锚定设计（关键一节）

- **三档法**：基础/专业/旗舰，主推中间档（标"最受欢迎"）。单一定价=把决策权交给用户犹豫。
- **年付锚**：月付价格旁边放年付价，月付就显得贵，年付转化自然上来。
- **免费锚**：免费版 ¥0 往那一放，¥19/月就显得"也就一杯奶茶钱"。

### 4.4 价格测试（上线后）

不要一次定死。用 A/B 或分批调价：

1. 先定一个"略贵"的价格上线（降价容易，涨价难）
2. 看 100 个访问的付费转化：<1% 考虑降价或加强价值传达；>5% 考虑涨价
3. 每次只动一个变量（价格或档位），记录数据

## 5. 定价页必备要素清单（审计脚本会查）

输出 pricing.md 时，以下要素缺一不可：

- [ ] 具体价格数字（含货币单位与计费周期，如 ¥19/月）
- [ ] 目标人群说明（适合谁、不适合谁）
- [ ] 免费版/试用说明（冷启动的低门槛入口）
- [ ] 退款政策（推荐 7 天无理由）
- [ ] 订阅可随时取消（订阅制必备）
- [ ] 自动续费的到期提醒说明
- [ ] 支付方式（支付宝/微信支付/Stripe 等）
- [ ] 竞品对标（一句话就行）
- [ ] FAQ（至少 3 条：发票/退款/学生优惠）
- [ ] **合规声明**（见第 6 节）

## 6. 合规声明（必写，原样或改写保留原意）

> 支付与税务合规因国家/地区而异：以上定价为通用框架，
> 涉及发票、税务申报、公司主体等问题，请以当地法规为准，
> 必要时咨询专业人士（如会计师/律师）。本插件不做具体税务法律建议。

**红线**：本 skill 只给通用框架，绝不给具体税务/法律建议。
用户问"我要不要注册公司""怎么报税最省"→ 回答固定话术：
"这取决于你所在地的法规，建议咨询当地会计师/律师，我只能给你通用框架。"

## 7. 定价话术：怎么跟用户谈钱

定价页之外的三个场景，话术提前准备好：

- **用户嫌贵**：不要降价，先问"您觉得贵，是跟什么比？"——比出参照系，
  再讲差异点。实在谈不拢，给年付折扣（保住价格锚）。
- **老用户涨价**：提前 30 天邮件通知 + 老用户维持原价 12 个月（grandfather）。
  涨价信模板三段：感谢→成本/价值变化→老用户权益。
- **免费用户问"以后会收费吗"**：诚实回答路线图——"免费版永久保留这些功能，
  高级功能走付费版"。含糊其辞透支信任。

## 8. 反模式（别踩）

1. **免费陷阱**："先免费做大再说"——一人公司没有"再说"，免费用户越多服务器账单越贵。
2. **$9.99 情结**：看到海外独立开发者定 $9 就跟风。你的成本结构、用户付费习惯可能完全不同。
3. **价格自卑**："我这个小工具好意思收钱吗？"——用户为解决的问题付费，不为你的代码行数付费。
4. **终身会员乱卖**："终身 ¥199"卖得越多，未来的你越想哭。除非你算过 LTV，否则别碰"终身"。
5. **涨价羞耻**：成本涨了、价值涨了，价格就该涨。老用户 grandfather（维持原价）是体面的做法。

## 9. 自检与反馈

### 9.1 质检门（每次使用后自查）

- [ ] 定价模型（三选一）写清楚了，且写了"为什么选它"？
- [ ] 价格数字有货币单位和计费周期吗？
- [ ] 退款/取消/自动续费提醒三件套齐了吗？
- [ ] 合规声明在 pricing.md 里吗？一字不差或保留原意改写？
- [ ] 有没有收入承诺式表述（"月入 X 万"）？有则必须配"不构成承诺/因人而异"免责，或删掉。
- [ ] 跑一遍 `python3 scripts/audit/indie_audit.py --target <文档目录>`，blocker 必须为 0。

### 9.2 标准冒烟用例

输入：`"番茄钟 App，目标用户自由职业者，P0：计时/任务/统计"`
期望输出：pricing.md 包含三模型选型结论、≥2 档价格（含 ¥/周期）、
退款+取消+续费提醒、支付方式、竞品对标、FAQ、合规声明；
审计脚本 0 blocker。
