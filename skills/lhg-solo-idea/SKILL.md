# lhg-solo-idea：想法验证与机会判断

> 目标：把"我有个想法"变成"这个想法值不值得我花 2 周"的明确结论。
> 核心纪律：**没有验证付费意愿的想法，不进入 MVP 阶段。**一人公司最大的成本不是服务器，是时间。

## 1. 何时使用

- 用户说"我想做个 XX"，只有一个模糊想法时 → 必须先跑本 skill
- 已有多个想法、不知道先做哪个时 → 用第 4 步的打分卡排序
- 想法已经验证过（有预付费用户/明确订单）→ 可跳过，直接进 lhg-solo-mvp

## 2. 输入与输出

- **输入**：一句话产品想法（越模糊越好，这是起点）
- **输出**：一份 `idea-brief.md`，包含：问题陈述、目标用户、付费意愿证据、竞品速览、做/不做决策

## 3. 第一步：问题真实性（灵魂三问）

不要问"这个想法好不好"，要问"这个问题真不真"。按顺序问用户（一次 1-2 个）：

1. **谁在疼？**——"这个问题具体是谁的？能说出 3 个真人（朋友/网友/自己）吗？"说不出具体的人，问题就是假想的。
2. **疼多久了？**——"他们为这个问题难受多久了？现在用什么土办法对付？"用土办法超过 3 个月 = 真问题；刚冒出来 3 天 = 伪需求。
3. **愿意付钱吗？**——"他们现在为土办法付了多少钱（时间/金钱）？"不付钱的问题不值得做产品，只值得写文章。

### 3.1 停止条件

- 三个问题都有具体答案 → 进入第二步
- 答不上来 → 给用户 48 小时去访谈 3 个人，回来再继续（不要脑补答案）

## 4. 第二步：付费意愿测试（一人公司的试金石）

按成本从低到高，选一级做：

1. **Landing Page 测试**（推荐）：1 页落地页讲清楚价值 + 定价 + "留下邮箱/付定金"，投到 1-2 个目标社区，看 100 个访问里有没有 3% 留资。没人留资 = 想法先冻起来。
2. **预售测试**：直接卖，收 1 元定金或全款预售。收到第一笔真实付款 = 验证通过。这是含金量最高的验证。
3. ** concierge 测试**：人工冒充产品服务 5 个用户（如手动帮人做报表），看对方愿不愿意为"人工版"付费。

**红线**：问卷"我会买吗"不算验证，只有"掏钱/留资/持续用"算数。

## 5. 第三步：竞品速览（30 分钟速成）

1. 列出 3-5 个直接竞品（一句话：它解决什么、收多少钱）。
2. 回答三个问题：
   - 它们为什么没做好？（差评区是最好的老师）
   - 我比它们好在哪？（一句话差异点，说不出来就别做）
   - 它们最大的用户从哪来？（抄作业：渠道可以直接复用）
3. **做不做的关键判断**：有巨头在做 ≠ 不能做；判断标准是"巨头愿不愿意为这个小市场调转船头"。小而美的市场是独立开发者的护城河。

## 6. 第四步：做/不做决策门

用打分卡（每项 1-5 分，总分 20）：

| 维度 | 5 分长什么样 |
|---|---|
| 问题真实性 | 3 个以上真人明确表达痛点，且在用土办法付费解决 |
| 付费意愿 | 已有留资/预售/真实付款 |
| 差异点 | 一句话说清和竞品的区别，且竞品 3 个月内抄不走 |
| 一人可做 | 2 周能做出 MVP，一个人能运维 |

- **≥15 分**：做，进 lhg-solo-mvp
- **10-14 分**：补验证（回去做第二步），2 周后再评
- **<10 分**：杀掉，想法存档，不纠缠。一人公司最贵的是"不甘心"。

## 7. 用户访谈话术模板（拿去直接用）

找 3-5 个目标用户，每人 15 分钟，按这个脚本聊：

1. 开场："我在了解 [某类问题]，想听听你的真实经历，不是要卖你东西。"
2. 挖痛点："上次被这个问题折腾是什么时候？当时具体发生了什么？"
3. 挖土办法："你现在怎么对付它？这个办法最烦人的地方在哪？"
4. 挖付费："为这个土办法，你花过钱/花过多少时间？如果有个工具能省掉一半时间，你愿意付多少？"
5. 收尾："如果我做出来了，可以第一个找你试用吗？留个联系方式？"

**记录要求**：原话记录，不要总结。访谈完把"愿付金额"和"留资意愿"填进打分卡，
这就是第二步的付费意愿证据。

## 8. 打分卡实战示例

以"帮自由职业者自动记账报税的 App"为例：

| 维度 | 得分 | 依据 |
|---|---|---|
| 问题真实性 | 4 | 访谈 5 人，4 人用 Excel 土办法记账，每月花 2 小时对账 |
| 付费意愿 | 2 | 只有 1 人留了邮箱，无人愿意预付；需补 Landing Page 测试 |
| 差异点 | 3 | 差异点是"自动同步银行流水"，但竞品 3 个月能抄上 |
| 一人可做 | 2 | 银行接口对接+税务规则，一人 2 周做不完，需砍到"手动导入+模板" |

总分 11 → **补验证**：先砍范围到"手动导入记账"，再跑 Landing Page 测试，
2 周后重评。注意合规：凡涉及报税表述，必须带"税务合规因国家而异，
以当地法规为准"的提醒，这是审计脚本 SOLO-CMP-001 的硬门。

## 9. 常见想法类型的验证捷径

不同赛道，验证的"最短路径"不一样：

- **效率工具**：直接做 Landing Page + 假按钮（"立即使用"点进去是"留下邮箱，内测中"），
  看点击率。工具类用户行动快，问卷没用，行为数据说了算。
- **内容/社区产品**：先建群/开账号，用人工运营跑 2 周。有人天天来、有人主动拉人，
  再考虑做产品。没人来的群，做成 App 也没人来。
- **交易/撮合**：concierge 测试是唯一解。手动撮合 5 单，收得到钱再做系统。
  撮合类死法最多的是"系统搭好了，两边都不来"。
- **AI 应用**：用现成大模型 API 拼一个 demo，给 10 个人用，看 7 日留存。
  留存 < 20% 说明 prompt 包一层皮没有壁垒，先找差异点。
- **出海产品**：验证渠道和验证产品同样重要。先在目标渠道（如 Reddit/ indie hackers）
  发 3 篇内容，看自然流量和回复质量，再决定做不做英文版。

## 10. 反模式（别踩）

1. **功能清单式验证**："我这个有 20 个功能所以比竞品好"——用户为解决一个问题付费，不为功能数量付费。
2. **问朋友"好不好"**：朋友都会说好。要问陌生人，要看掏钱。
3. **大而全的野心**："做个平台""做个生态"——一人公司做平台，等于一个人盖商场。
4. **技术驱动选型**："我想学 Rust 所以用 Rust 做"——学技术去做 side project，赚钱的产品用你最熟的栈。
5. **保密情结**："想法说了会被抄"——执行力才是壁垒，想法说出来才能获得反馈。

## 11. 自检与反馈

### 11.1 质检门（每次使用后自查）

- [ ] idea-brief.md 里有没有 3 个真人用户（不是"目标用户画像"这种空话）？
- [ ] 付费意愿证据是真实行为（留资/付款/持续用），还是问卷口嗨？
- [ ] 打分卡四项都打了分，且结论明确（做/补验证/杀掉三选一）？
- [ ] 有没有出现具体数字编造（如"市场规模 500 亿"却无来源）？有则删掉或标注来源。

### 11.2 标准冒烟用例

输入：`"做个帮自由职业者自动记账报税的 App"`
期望输出：idea-brief.md 包含灵魂三问答案、至少一级付费意愿测试方案、
3 个竞品、打分卡与明确结论；且**必须包含合规提醒**（税务合规因国家而异，
以当地法规为准）——缺合规提醒算质检不通过。

### 11.3 一键提 issue

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到
https://github.com/lhg-plugs/lhg-solopreneur/issues，
正文写清"复现步骤 → 实际表现 → 期望表现"。
